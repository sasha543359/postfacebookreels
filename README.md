# 📘 Facebook Reels Publisher

Следит за TikTok-аккаунтами и автоматически публикует их новые ролики в **Facebook Reels**.

То же самое, что [InstagramVideoPublisher](https://github.com/sasha543359/InstagramVideoPublisher),
только публикует не в Instagram, а на Страницы Facebook.

![Graph API](https://img.shields.io/badge/Graph%20API-v26.0-blue)

> Части 1–2 (приложение, Страница, токен) и сама публикация проверены вживую на новом аккаунте Facebook 18.09.2026; установка на дроплет (Части 3–4) вживую пока не проверялась.

> **Разворачиваешь на сервере?** → [`DEPLOY.md`](DEPLOY.md), там весь путь по шагам.
> Все настройки — в одном файле [`appsettings.json`](appsettings.json), каждое поле подписано.

> `appsettings.json` — обе команды, иначе проверятся старые настройки, вшитые в образ):
> `docker compose build && docker compose run --rm app --check`

## Что делает

1. Раз в несколько минут обходит список TikTok-авторов.
2. Находит ролик, которого ещё не публиковал.
3. Скачивает его в максимальном качестве (`yt-dlp`), без водяного знака.
4. Прогоняет через уникализатор (`ffmpeg`): кроп, цвет, скорость, звук — своя
   сигнатура под каждую Страницу, чтобы один исходник на разных Страницах давал
   разные файлы.
5. Публикует как Reels на Страницу Facebook.
6. Удаляет локальный файл и запоминает ID ролика, чтобы не выложить его дважды.

## Чем отличается от Instagram-версии

| | Instagram | Facebook |
|---|---|---|
| Куда публикует | аккаунт Business/Creator | **только Страница** (личный профиль API не поддерживает) |
| Запросов на публикацию | 2 (контейнер → публикация) | **3** (start → загрузка → finish) |
| Хост | `graph.instagram.com` | `graph.facebook.com` + **`rupload.facebook.com`** для загрузки |
| Как отдаётся файл | только ссылкой (`video_url`) | **байтами напрямую** (по умолчанию) или ссылкой |
| Обложка | ссылкой (`cover_url`) | файлом, отдельным запросом `/thumbnails` |
| Длительность | до 90 сек | **3–90 сек** (длиннее — подрезаем сами) |
| Лимит | свой | **30 публикаций на Страницу за 24 часа** (лимит самого Facebook) |
| Токен | ~60 дней | **бессрочный**, если получен правильно (см. ниже) |

Главное практическое отличие: **токен Страницы не протухает**. Токен Instagram
приходилось перевыпускать каждые 60 дней — здесь, если получить его по шагам
ниже (через долгоживущий пользовательский токен), он живёт бессрочно.

Второе: **файл не надо выкладывать наружу**. В Instagram публичная ссылка была
обязательна, а здесь по умолчанию стоит `"UploadMode": "bytes"` — программа сама
заливает файл в Facebook, и Nginx с белым IP для этого не нужны. Этот режим
проверен вживую. Отдача ссылкой тоже есть, но она необязательная (см. ниже,
«Как отдавать видео Facebook»).

## Настройка приложения Facebook

### ⚠️ Сначала прочти это

**Не добавляй Pages-сценарий в приложение, которым публикуешь в Instagram.**

Meta пишет прямым текстом: **«Сценарии использования нельзя удалить после
создания приложения»**, и часть сценариев несовместима между собой. Если
добавить «Управляйте всем на своей Странице» в приложение с Instagram-сценарием
и они не поладят, откатить это будет нечем — приложение придётся бросить.

**Заведи отдельное приложение под Facebook Reels.** Это 5 минут, и
Instagram-публикатор продолжит работать как работал.

### Шаги

1. https://developers.facebook.com/apps → **Создать приложение**.
   В названии нельзя слов facebook, face, book, insta, gram, FB, Rift — отказ
   появится красным после «Далее».
2. Слева фильтр **«Управление контентом»** → **«Управляйте всем на своей Странице»**.
3. Бизнес-портфолио: **«Я пока не хочу подключать бизнес-портфолио»**; на экране
   требований «Требования не найдены» — так и надо.
4. В настройке сценария (всплывёт подсказка «Узнайте, как настроить сценарии
   использования» → «Готово») нажать **«Добавить»** напротив:
   - `pages_read_engagement`
   - `pages_manage_posts`
   - `pages_read_user_content`, `pages_manage_engagement` — нужны только для
     своей обложки.

   (`pages_show_list`, `public_profile`, `business_management` уже «Готово к
   тестированию».)
5. Приложение **оставить в режиме разработки** («Не опубликовано»).
   Проверка приложения (App Review) для публикации на СВОИ Страницы **не нужна**,
   бизнес-верификация тоже.

### Нужно ли «добавлять аккаунты», как в Instagram?

Отдельно привязывать Страницу к приложению **не нужно** — достаточно, чтобы
человек, от чьего имени выпущен токен, был администратором Страницы.

А вот **людей** добавлять нужно, и это важно, если раздаёшь проект друзьям.
Пока приложение в режиме разработки, выдать ему разрешения может **только тот,
у кого есть роль в приложении**. Поэтому у друга есть два пути:

- **своё приложение** (проще и правильнее — токены и лимиты у каждого свои);
- либо ты добавляешь его в **«Роли в приложении» → «Роли» → Тестировщики**.
  Тестировщики не видят App Secret, так что это безопасно.

## Как получить токен Страницы (бессрочный)

Самая частая ошибка — на шаге 4. Читай внимательно.

0. Нужна **Страница** Facebook: https://www.facebook.com/pages/create —
   название и категория, больше ничего. На новом аккаунте кнопка «Создать
   Страницу» может молча не реагировать: это лимит Facebook на создание
   Страниц, сообщения он не показывает. Не жми много раз — подожди и
   попробуй позже.
1. Открыть **Graph API Explorer**: https://developers.facebook.com/tools/explorer/
2. Справа вверху **Meta App** → выбрать своё приложение.
   **User or Page** → **Get User Access Token**.
3. Отметить разрешения: `pages_show_list`, `pages_read_engagement`,
   `pages_manage_posts` (если нужна своя обложка — ещё `pages_read_user_content`
   и `pages_manage_engagement`) → **Generate Access Token**. Откроется **отдельное
   окно** входа Facebook — в нём выбрать **«Разрешить для всех текущих и
   будущих Страниц»** → «Продолжить» → **«Сохранить»**.
   Получился короткий пользовательский токен (живёт 1–2 часа).
4. **Обменять его на долгоживущий** (60 дней). В браузере:

   ```
   https://graph.facebook.com/v26.0/oauth/access_token?grant_type=fb_exchange_token&client_id=ID_ПРИЛОЖЕНИЯ&client_secret=СЕКРЕТ_ПРИЛОЖЕНИЯ&fb_exchange_token=КОРОТКИЙ_ТОКЕН
   ```

   App ID и App Secret лежат в **Настройки приложения → Основное**
   (секрет показывается после повторного ввода пароля Facebook).

5. **Долгоживущим** токеном из шага 4 запросить Страницы:

   ```
   https://graph.facebook.com/v26.0/me/accounts?access_token=ДОЛГОЖИВУЩИЙ_ТОКЕН
   ```

   В ответе по каждой Странице: `name`, **`id`** (это `PageId`),
   **`access_token`** (это `PageAccessToken`) и `tasks`.
   Убедись, что в `tasks` есть **`CREATE_CONTENT`**.

6. Проверить на https://developers.facebook.com/tools/debug/accesstoken/ —
   тип **Page**, в строке **«Истекает»** (Expires) — **«Никогда»** (Never).
   «Доступ к данным истекает» через 3 месяца — это нормально: разрешения
   `pages_*` у Meta не истекают, публикация не остановится.

> **Если пропустить шаг 4** и звать `/me/accounts` коротким токеном, токен
> Страницы тоже будет коротким и умрёт через час-два. Ровно это ломается чаще всего.

Токен Страницы, полученный так, не имеет срока. Отозвать его могут только
смена пароля Facebook, смена App Secret, отзыв доступа приложению вручную или
снятие тебя с роли администратора Страницы.

## Запуск

### На сервере

Всё по шагам: [`DEPLOY.md`](DEPLOY.md). Коротко:

```bash
bash setup.sh                 # ставит Docker, Nginx, папки
nano appsettings.json         # вписать PageId, PageAccessToken, TikTokUsernames
docker compose up -d --build
docker compose logs -f app
```

### Локально

```bash
dotnet restore
dotnet run -- --check         # проверка без публикации
dotnet run                    # рабочий цикл
```

Локально нужны `yt-dlp`, `ffmpeg`/`ffprobe` и Python в PATH. Локальные пути
положи в `appsettings.Development.json` рядом с `appsettings.json` (он в
`.gitignore` и читается поверх основного при запуске без `ASPNETCORE_ENVIRONMENT`):

```json
{ "TikTokMonitor": { "YtDlpPath": "yt-dlp", "DownloadPath": "./videos" },
  "Uniquifier": { "PythonPath": "python", "ScriptPath": "uniquify.py", "Font": "C:/Windows/Fonts/arialbd.ttf" },
  "Publishing": { "CountsPath": "./videos/post_counts.json" },
  "Server": { "UploadMode": "bytes", "CoverPath": "./videos/covers" } }
```

Без `ScriptPath` уникализатор не запустится и уйдёт исходник.

## Режим проверки

```bash
docker compose build && docker compose run --rm app --check
```

`docker compose build` нужен после каждой правки `appsettings.json`: настройки
вшиваются в образ при сборке, и без пересборки проверятся старые.

Проходит по всем Страницам и авторам и **ничего не публикует**. Показывает:

- живой ли токен у каждой Страницы и та ли это Страница;
- читается ли лента каждого TikTok-автора и когда вышел последний ролик.

С `--download` вдобавок скачивает по одному ролику с каждого автора — это
проверяет вторую половину пути, которая ломается отдельно от первой:

```bash
docker compose build && docker compose run --rm app --check --download
```

Можно указать конкретных авторов:

```bash
docker compose build && docker compose run --rm app --check nasa shotstroy
```

## Настройки, которые спрашивают чаще всего

### Описание под роликом

Собирается так: **текст → обязательная подпись → хэштеги** (через пустую строку).

- `CustomCaption` у Страницы — свой текст вместо описания из TikTok.
  Пусто → берётся описание исходного ролика (обрезается до 1500 символов).
- `RequiredCaptionSuffix` (общая, одна на весь файл) — строка, которая
  добавляется к **каждой** публикации. По умолчанию `Twitch: MELLSTROY`.
  Если она уже есть в тексте, второй раз не дублируется.
- `DefaultHashtags` (общая) — хэштеги в конце, по умолчанию
  `#мемы #приколы #юмор #рилс`. Дописываются, **только если в тексте нет ни
  одного `#`**. Пусто → хэштеги не дописываются.

Все три — обычные поля в `appsettings.json`.

### Сколько публиковать

```jsonc
"Publishing": {
  "MaxPostsPerPagePerDay": 5,    // своих публикаций на Страницу за 24 часа
  "MinMinutesBetweenPosts": 3,   // пауза между публикациями одной Страницы
  "ApiHardLimitPer24h": 30       // потолок Facebook, не трогать
}
```

Окно — **скользящие 24 часа**, а не календарные сутки: так же считает сам
Facebook. Поэтому «5 постов» означает «не больше 5 за любые 24 часа подряд»,
а не «5 до полуночи и ещё 5 после».

### Обложка

Положить картинку в `/var/www/videos/covers/` и указать **имя файла**:

```jsonc
"CoverImage": "cover.jpg"
```

Требования: JPG или PNG, 1080×1920, до 10 МБ.

Обложке нужны ещё два разрешения — `pages_read_user_content` и
`pages_manage_engagement`. Их надо и добавить в приложение, и отметить в Graph
API Explorer при выпуске токена (шаг 3). Если токен уже получен без них —
пройди шаги 3–5 заново и вставь новый `PageAccessToken`. Без них ролик всё
равно выйдет, просто с кадром из видео, а в логе будет предупреждение.

### Как отдавать видео Facebook

```jsonc
"UploadMode": "bytes"   // в блоке Server
```

- `"bytes"` — **по умолчанию, рекомендуется.** Программа сама заливает файл
  в Facebook. Публичный адрес (`PublicUrl`) и Nginx для этого не нужны.
  Проверено вживую 18.09.2026.
- `"url"` — только ссылкой: Facebook сам скачивает ролик с твоего сервера по
  `PublicUrl`. Нужен рабочий публичный адрес. Вживую пока не проверялся.
- `"auto"` — сначала ссылкой. На заливку файлом переходит, **только если
  Facebook сразу отказался принять ссылку**. Если ссылку он принял, но скачать
  файл не смог, — публикация проваливается, и в следующем цикле программа
  снова пробует ссылку. Вживую тоже не проверялся.

Не уверен — оставляй `"bytes"`.

### Файл удаляется после публикации?

Да. Скачанный и обработанный ролик удаляется сразу после публикации — и при
ошибке тоже. На диске ничего не копится. Остаются только два маленьких
служебных файла в `/var/www/videos`:

- `video_history.json` — что уже публиковали (последние 5 ID на пару
  «Страница : автор»);
- `post_counts.json` — счётчик для анти-спама.

Оба удалять нельзя: без истории программа сочтёт запуск первым и промолчит,
пока у каждого автора не выйдет новый ролик.

### Аудитория: русскоязычные зрители (СНГ и Европа)

- **«Ограничения по странам»** (Страница → Настройки → «Подписчики и
  общедоступный контент») оставь **пустыми**. Это не «показывать в первую
  очередь», а «скрыть Страницу везде, **кроме** этих стран»: список «Россия,
  Беларусь, Украина» спрячет её от русскоязычных в Европе и Израиле. К тому же
  в России Facebook заблокирован с 2022 года, зрители оттуда смотрят через
  VPN — ограничение по странам отрезало бы и их. Пусто = видно везде.
- Текст — по-русски: `CustomCaption`, `RequiredCaptionSuffix`,
  `DefaultHashtags`. Учти: `DefaultHashtags` не дописываются, если в тексте уже
  есть хоть один `#` (у англоязычного автора с `#fyp` русских хэштегов не
  будет) — тогда задай русский `CustomCaption`.
- Оформи Страницу по-русски: «Информация» → «Краткая биография» (до 255
  символов).

## Требования Facebook к видео

Программа приводит ролики к этим требованиям сама (уникализатором), но знать
полезно:

| Параметр | Требование |
|---|---|
| Контейнер | mp4 |
| Соотношение сторон | 9:16 |
| Разрешение | 1080×1920 (минимум 540×960) |
| Частота кадров | 24–60 к/с |
| **Длительность** | **3–90 секунд** |
| Видео | H.264 или H.265, yuv420p, прогрессивная развёртка |
| Звук | AAC-LC, 48 кГц, стерео, от 128 кбит/с |

**Про 90 секунд.** Роликов длиннее в TikTok много, и Facebook их не принимает.
Программа подрезает такие сама, до 89,5 секунды (не до 90: резка без пережатия
промахивается на сотые вверх) — даже с выключенным уникализатором. Без подрезки
Facebook отказал бы, и ролик был бы потерян: такой отказ окончательный,
программа помечает ролик обработанным и больше его не пробует.

## Когда что-то не работает

Смотреть логи:

```bash
docker compose logs -f app          # живой поток
docker compose logs --tail 100 app  # последние 100 строк
```

Программа расшифровывает коды ошибок Facebook прямо в логе. Самые частые:

| Что в логе | Что делать |
|---|---|
| `код 190` — маркер недействителен | получить новый токен Страницы (шаги выше) |
| `код 200` — не хватает прав | добавить `pages_manage_posts`, проверить `CREATE_CONTENT` |
| `код 613` — лимит | 30 публикаций за 24 часа уже сделано, подождать |
| `код 1363128` — длительность | ролик не 3–90 секунд |
| `код 1363127` — разрешение | меньше 540×960 |
| `код 1363040` — соотношение сторон | не между 16:9 и 9:16 |
| `⏭️  Facebook не примет этот ролик` | Facebook забраковал сам файл (часто уже после finish). Ролик помечен обработанным и больше не пробуется — это нормально |
| `Facebook принял Reels, но выход ещё не подтвердился` | finish прошёл без ошибок; ролик засчитан опубликованным и выйдет сам. Проверь Страницу через пару минут |
| `Загрузка не подтвердилась за …с` | Facebook не подтвердил получение файла, программа всё равно пробует опубликовать. Если следом пришла ошибка, а в `UploadMode` стоит `"url"` или `"auto"` — поставь `"bytes"` |
| `статус не прочитался (…) — спрашиваем ещё раз` | сбой связи при опросе, не отказ; ничего делать не надо |
| `⛔ TikTok не знает @ник` | автор удалён или сменил ник — править `TikTokUsernames` |
| `Unexpected response from webpage request` | TikTok блокирует IP сервера, см. ниже |

### TikTok блокирует сервер

Дата-центровые адреса (а дроплет — именно такой) TikTok блокирует охотнее
домашних. Признаки: ленты не читаются, в логе `Unexpected response from
webpage request` или `Unable to extract universal data for rehydration`.

Что помогает, по порядку:

1. Подождать — блокировки часто временные.
2. Увеличить `TikTokCheckDelaySeconds` (например до 60).
3. Прописать прокси в `ExtraYtDlpArgs`:
   ```jsonc
   "ExtraYtDlpArgs": "--proxy socks5://user:pass@host:port"
   ```

Запасной путь у программы есть и так: если `yt-dlp` не справился за 5 попыток,
ролик качается по прямой ссылке с embed-страницы. Качество будет ниже
(576×1024 вместо 1080×1920), но ролик выйдет.

### ⚠️ Не обновляй `curl-cffi` вручную

В образе она закреплена на версии **0.16.0**, и это не случайность.
Начиная с 0.16.1 появляется отпечаток браузера `chrome-150`, который `yt-dlp`
выбирает автоматически, а **TikTok блокирует его наглухо**
([yt-dlp #17604](https://github.com/yt-dlp/yt-dlp/issues/17604)).

`pip install -U curl-cffi` внутри контейнера сломает скачивание. При старте

### Алгоритм обхода — «карусель»

Берётся первый автор у каждой Страницы, потом второй, и так далее:

```
Страница#1→автор[0], Страница#2→автор[0], …, Страница#1→автор[1], …
```

Так ни одна Страница не съедает весь цикл, если у неё длинный список авторов.
Поэтому списки `TikTokUsernames` лучше держать примерно равной длины.

### Как публикуется ролик

```
1. start    POST graph.facebook.com/v26.0/{page-id}/video_reels
            {"upload_phase":"start"}                    → video_id

2. загрузка POST rupload.facebook.com/video-upload/v26.0/{video_id}
            ссылкой: заголовок file_url
            байтами: Authorization + offset + file_size + тело       → {"success":true}

3. ожидание GET  graph.facebook.com/v26.0/{video_id}?fields=status
            пока uploading_phase не станет complete (файл у Facebook)

4. обложка  POST graph.facebook.com/v26.0/{video_id}/thumbnails      (необязательно)

5. finish   POST graph.facebook.com/v26.0/{page-id}/video_reels
            ?upload_phase=finish&video_state=PUBLISHED&description=…  → {"success":true}

6. итог     GET  graph.facebook.com/v26.0/{video_id}?fields=status
            пока publishing_phase не станет complete (или video_status ready)
```

Обработку видео Facebook запускает **только после finish** — до него
`processing_phase` стоит в `not_started` (проверено вживую). Поэтому до finish
ждём лишь загрузку, а отказ по самому файлу (разрешение, длительность) ловим на
шаге 6. После finish ролик выходит за 10–60 секунд (замер 18.09.2026), плюс
время на заливку файла.

Шаг 2 — единственный, который идёт на `rupload.facebook.com`. Отправить его на
`graph.facebook.com` — самая частая ошибка при переносе с Instagram.
