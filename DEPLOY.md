# Разворачивание на DigitalOcean

Инструкция для чистого дроплета Ubuntu. Делать всё по порядку, ничего не
пропуская.

**`ТВОЙ_IP`** ниже — это IP твоего дроплета. Все команды, кроме шага 0, —
на сервере под `root`.

---

## Что понадобится

- Дроплет Ubuntu (хватит самого дешёвого, **2 ГБ памяти** — комфортно;
  на 1 ГБ тоже поедет, скрипт сам добавит подкачку).
- Страница Facebook, где ты администратор.
- `PageId` и `PageAccessToken` для неё — как получить, написано в
  [`README.md`](README.md), раздел «Как получить токен Страницы».

---

## Шаг 0 — залить проект на сервер

На **своём компьютере**, в PowerShell:

```powershell
cd C:\Users\sasha\Desktop\postfacebookreels
ssh root@ТВОЙ_IP "mkdir -p /opt/facebook-reels-publisher"
scp -r ./* root@ТВОЙ_IP:/opt/facebook-reels-publisher/
```

> Первый `ssh` спросит про отпечаток ключа — ответить `yes`.
> Пароль при вводе не отображается, это нормально.

## Шаг 1 — зайти на сервер

```bash
ssh root@ТВОЙ_IP
```

---

## Шаг 2 — запустить установщик

```bash
cd /opt/facebook-reels-publisher
bash setup.sh
```

Скрипт сам поставит Docker, Nginx, создаст папки, добавит подкачку и напишет
серверный `docker-compose.yml`. Занимает 2–5 минут.

В конце он проверит, открываются ли видео по ссылке `http://ТВОЙ_IP/videos/…`,
и напишет результат. **Что бы он ни написал, делать ничего не надо:** в
`appsettings.json` по умолчанию стоит `"UploadMode": "bytes"` — проверенный
режим, видео заливается в Facebook файлом, публичный адрес и Nginx ему не
нужны. Проверка скрипта — только для сведения: она идёт с самого сервера на
его же адрес и закрытый снаружи порт может не заметить.

---

## Шаг 3 — вписать свои данные

```bash
nano /opt/facebook-reels-publisher/appsettings.json
```

Поменять нужно три вещи:

| Что | Где | На что |
|---|---|---|
| `PageId` | у каждой Страницы | числовой ID Страницы |
| `PageAccessToken` | у каждой Страницы | токен Страницы |
| `TikTokUsernames` | у каждой Страницы | ники TikTok без `@` |

> **У Страниц, которыми не пользуешься, `PageAccessToken` должен быть пустой
> строкой `""`.** Заглушка `ВСТАВЬ_PAGE_ACCESS_TOKEN` — не пустая, программа
> сочтёт её рабочей и будет сыпать ошибками.

`PublicUrl` внизу, в блоке `Server`, можно оставить как есть: при
`"UploadMode": "bytes"` (стоит по умолчанию) он не используется. Вписывать
туда `http://ТВОЙ_IP` нужно, только если сам переключишь режим на `"url"`
или `"auto"`.

На самой Странице «Ограничения по странам» не заполнять — см. README, «Аудитория».

Сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.

---

## Шаг 4 — проверить, не публикуя

```bash
cd /opt/facebook-reels-publisher
docker compose build && docker compose run --rm app --check
```

Первый раз сборка займёт 2–5 минут — это нормально. После любой правки
`appsettings.json` запускай эту команду целиком: без `docker compose build`
проверятся старые настройки, вшитые в образ.

Должно получиться две таблицы:

- Страницы Facebook → в колонке «Итог» зелёное `Страница «Название» (id …)`;
- TikTok-авторы → в колонке «Итог» зелёное `лента читается`.

Если там красное — читай текст, он написан по-русски и говорит, что чинить.
**Дальше идти только после того, как проверка зелёная.**

---

## Шаг 5 — запустить

```bash
docker compose up -d --build
```

Образ уже собран на шаге 4, поэтому запуск займёт несколько секунд.

---

## Шаг 6 — смотреть логи

```bash
docker compose logs -f app
```

Видно весь процесс: проверку авторов, скачивание, уникализацию, три фазы
публикации. Выйти из просмотра — `Ctrl+C` (программа при этом продолжит
работать).

**Первый запуск ничего не публикует.** Программа запоминает последние 5 роликов
каждого автора и ждёт новых — иначе она бы разом выложила всё, что уже вышло.
Первая публикация будет, когда у кого-то из авторов появится свежий ролик.

## Повседневные команды

Все — из `/opt/facebook-reels-publisher`.

| Что нужно | Команда |
|---|---|
| Смотреть логи | `docker compose logs -f app` |
| Последние 100 строк | `docker compose logs --tail 100 app` |
| Остановить | `docker compose down` |
| Запустить | `docker compose up -d` |
| Перезапустить | `docker compose restart app` |
| Работает ли | `docker compose ps` |
| Проверить настройки | `docker compose build && docker compose run --rm app --check` |
| Список обложек | `ls -la /var/www/videos/covers/` |

## Поменять настройки

Токены, ники TikTok, описание, лимиты — всё в одном файле:

```bash
cd /opt/facebook-reels-publisher
nano appsettings.json
# правки → Ctrl+O, Enter, Ctrl+X
docker compose up -d --build
```

> **`--build` обязателен.** `appsettings.json` вшивается в образ при сборке,
> поэтому просто `docker compose up -d` поднимет старые настройки, и будет
> казаться, что правки не применились.

Останавливать через `down` перед этим не надо — `up -d --build` сам пересоберёт
и перезапустит.

> то есть сотрёт серверные правки. Либо после копирования повтори шаги 2 и 3,

## Обложка

1. Залить картинку (с своего компьютера):

   ```powershell
   scp "C:\Users\sasha\Desktop\cover.jpg" root@ТВОЙ_IP:/var/www/videos/covers/
   ```

2. Указать **имя файла** в `appsettings.json` у нужной Страницы:

   ```jsonc
   "CoverImage": "cover.jpg"
   ```

3. `docker compose up -d --build`

Требования: JPG или PNG, 1080×1920, до 10 МБ. Регистр в имени важен —
`cover.jpg` и `Cover.JPG` для сервера разные файлы.

Убрать обложку — поставить `"CoverImage": ""` и пересобрать.

## Если что-то пошло не так

**Nginx не стартует, порт 80 занят**
Значит, поднялся вариант `docker-compose.yml` со встроенным Nginx. Должен быть
серверный, «только app» — его пишет `setup.sh` на шаге 2. Проверить:

```bash
cat /opt/facebook-reels-publisher/docker-compose.yml
```

Там должен быть только блок `app`, без `nginx`.

**`services must be a mapping`**
Слетели отступы в `docker-compose.yml` — почти всегда от копирования через
мессенджер. Перезапустить `bash setup.sh`, он перепишет файл заново.

**`compose is not a docker command`**

```bash
apt install docker-compose-plugin -y
```

**Сборка падает с кодом 137**
Не хватило памяти. `setup.sh` добавляет подкачку сам; если дроплет совсем
маленький, проверить, что она включилась:

```bash
free -h
```

**Публикация падает, а `--check` зелёный**
Смотреть текст ошибки в логах — коды Facebook расшифрованы по-русски.
Таблица частых кодов — в [`README.md`](README.md), раздел «Когда что-то не
работает».

**Facebook не забирает видео по ссылке**
Бывает, только если ты сам переключил `UploadMode` на `"url"` или `"auto"`.

На сервере:

```bash
echo ok > /var/www/videos/probe.txt
```

На **своём** компьютере, в PowerShell — должно ответить `ok`:

```powershell
curl.exe -A "facebookexternalhit/1.1" http://ТВОЙ_IP/videos/probe.txt
```

Потом на сервере:

```bash
rm /var/www/videos/probe.txt
```

Запрос к самой папке (`http://ТВОЙ_IP/videos/`) всегда даёт 403 — это
нормально, список файлов закрыт.

Если `ok` не пришёл — вернуть `"UploadMode": "bytes"` и пересобрать
(`docker compose up -d --build`). Программа будет заливать файлы напрямую,
публичный адрес не понадобится.
